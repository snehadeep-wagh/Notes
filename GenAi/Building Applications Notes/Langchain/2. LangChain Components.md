In langchain there are 6 main components - 
1) Models
2) Prompts
3) Chains
4) Memory
5) Indexes (RAG)
6) Agents

Below are the detailed notes for each component:
#### **1. Models**

Models are the core **interface** through which you interact with AI. LangChain solves a major "orchestration" problem here: standardizing how we talk to different AI providers.

- **The Problem:** Different companies (OpenAI, Google, Anthropic) have different API structures. If you want to switch from GPT-4 to Claude, you would normally have to rewrite your entire code.
- **The Solution:** LangChain provides a **standardized interface**. You can switch model providers by changing just one or two lines of code.
- **Two Types of Models Supported:**
    ## - **Language Models (LLMs):** 
	    "Text-in, Text-out" models used for chatting and generation.
    ### - **Embedding Models:** 
    - "Text-in, Vector-out" models. 
    - They turn text into numbers (vectors) to enable semantic search.
	- In Embedding models, generally **cosine** is used in semantic search because, in semantic search we are more focused on the direction. so if we have 2 vectors and we calculate the cosine then it will tell about the direction.
	
	Why only cosine? and not sine? - 
		- The answer is if there are 2 vectors in the same direction i.e. angle=0, then cos(0) = 1, 1 means maximum similarity and 0 means unrelated. 
		- In sine, sin(0) = 0, means 2 vectors having same direction will be marked as unrelated even though they have same direction.
	
	What are dimensions in embedding?
		- An embedding is just a list of numbers. The **number of values** is called the **dimension**.
		- example a = [1,2,3,4] the dimension of a is 4 as there are 4 elements 
	
	Why would you reduce dimensions?
		Imagine you have: 1 million documents
		With 3072 dimensions: 3072 numbers × 1,000,000
		That's a lot of storage.
		
		If you reduce to:512 dimensions
		you use much less storage and searches can be faster.
		
		There's a tradeoff:
		More dimensions → richer representation, but larger and slower.
		Fewer dimensions → faster and smaller, but you may lose some information.
	
	How do we choose the right dimension?
		There's no universal "best" value. It depends on your application.

| Use Case                       | Typical Choice |
| ------------------------------ | -------------- |
| Small chatbot                  | 384–768        |
| Document search                | 768–1024       |
| Large enterprise RAG           | 1024–3072      |
| Memory-constrained application | 256–512        |

	The best approach is to evaluate retrieval quality on your own data and balance accuracy, storage, and latency.

#### **2. Prompts**

Prompts are the inputs provided to an LLM. Because LLMs are highly sensitive to how a question is phrased, LangChain offers powerful ways to manage them.

- **Dynamic & Reusable Templates:** You can create prompts with placeholders (e.g., "Summarize `{topic}` in a `{tone}` tone") and fill them dynamically based on user input.

![[Pasted image 20260717030305.png]]

- **Role-Based Prompts:** You can define specific roles, such as telling the AI "You are an experienced doctor," to guide its expertise.

![[Pasted image 20260717030323.png]]

- **Few-Shot Prompting:** You can provide the model with a few examples of "input-output" pairs to help it understand the specific format or logic you want it to follow.

![[Pasted image 20260717030353.png]]


#### **3. Chains**

Chains allow you to build **pipelines** by linking different components together. This is where the name "LangChain" comes from.

- **Core Feature:** The output of one component automatically becomes the input for the next, eliminating the need for manual coding between steps.
- **Types of Chains:**
    - **Sequential:** Steps happen one after another (e.g., Translate text → Summarize translated text).
    - **Parallel:** Executing multiple tasks at the same time and combining their results into one final report.
    - **Conditional:** Branching logic where the AI decides the next step based on a condition (e.g., If feedback is "Bad," email support; if "Good," say "Thank you").

![[Pasted image 20260717030623.png]]


#### **4. Memory**

==**Standard LLM API calls are stateless**==, meaning the model "forgets" the previous message as soon as the next one starts. Memory components solve this by giving the AI a way to remember context.

- **Common Memory Types:**
    - **Conversation Buffer:** Stores and sends the entire chat history with every new request.
    - **Window Memory:** Only remembers the last 'N' messages to save on costs.
    - **Summarizer Memory:** Uses an LLM to summarize the past conversation, sending only the summary to save space.

#### **5. Indexes (RAG)**

Indexes connect your AI application to **external data** (like PDFs, private company databases, or websites) that the model wasn't originally trained on. This is the foundation of **Retrieval Augmented Generation (RAG)**.

- **The Workflow:**
    1. **Document Loader:** Brings in the external data.
    2. **Text Splitter:** Breaks large documents into smaller, manageable "chunks".
    3. **Vector Store:** Stores these chunks as numerical embeddings in a database.
    4. **Retriever:** When a user asks a question, this component finds the most relevant chunks and gives them to the LLM to provide an answer.

#### **6. Agents**

Agents are the most advanced component. While a chatbot just talks, an **Agent can take action**.

- **The Difference:** Agents use **Reasoning** to figure out which **Tools** they need to complete a task.
- **Example:** If you ask an agent to "Find the cheapest flight to Delhi and multiply the price by 3," the agent will:
    1. Reason that it needs a travel tool and a calculator.
    2. Call a **Weather/Flight API** to get the price.
    3. Call a **Calculator Tool** to perform the math.
    4. Return the final result to you.
