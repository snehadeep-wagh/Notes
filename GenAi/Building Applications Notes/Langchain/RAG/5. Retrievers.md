
**Retrievers** are the fourth and final core component of the RAG (Retrieval-Augmented Generation) pipeline discussed in this series. A retriever is a LangChain component that fetches relevant documents from a data source in response to a user's query.

## **1. Core Concept: What is a Retriever?**

Unlike a document loader that simply brings data into memory, a retriever includes "intelligence" to scan a data source (like a vector store or an API) and return only the documents most relevant to a specific query.

- **Input/Output:** It functions like a search engine: it takes a **string query** as input and returns a list of **Document Objects**.
- **Runnables:** Crucially, all retrievers in LangChain are **Runnables**. This means they can be seamlessly integrated into LangChain Expression Language (LCEL) chains using the pipe operator (`|`).

---

## **2. Categorization of Retrievers**

Retrievers can be differentiated by two main factors:

1. **By Data Source:** Which specific database or API they query (e.g., Wikipedia, Arxiv, Vector Stores).
2. **By Search Strategy:** The mathematical logic used to find "relevance" (e.g., MMR, Multi-Query, Contextual Compression).

---

## **3. Source-Based Retrievers**

#### **A. Wikipedia Retriever**

This retriever queries the Wikipedia API using **keyword matching** to fetch relevant articles.

- **How it works:** You provide a query; it hits the API and returns top-k relevant articles as Document objects.
- **Python Code Example:**

```
from langchain_community.retrievers import WikipediaRetriever

# 1. Create Retriever Object (top_k_results=2)
retriever = WikipediaRetriever(top_k_results=2)

# 2. Invoke (Retrievers are Runnables!)
docs = retriever.invoke("Geopolitical history of India")
print(docs.page_content) # Prints the first article's text [14, 15]
```

#### **B. Vector Store Retriever**

The most common type. It searches for documents in a vector store (like Chroma or FAISS) based on **semantic similarity** using vector embeddings.

- **Key Advantage:** It uses vector distance (e.g., cosine similarity) to find documents that mean the same thing even if they don't share keywords.
- **Python Code Example:**

```
# Assuming 'vector_store' is already created with documents
retriever = vector_store.as_retriever(search_kwargs={"k": 2})

# Execution
results = retriever.invoke("What is Chroma DB?") [18]
```

## **4. Strategy-Based (Advanced) Retrievers**

#### **A. MMR (Maximum Marginal Relevance)**

**Main Question:** How can we pick results that are not only relevant to the query but also different from each other? 

**Solution** - MMR is an information retrieval algorithm designed to reduce redundancy in the retrieved results while maintaining high relevance to the query.

#### Why MMR Retriever?

##### Step 1: Understanding the Problem

The text explains that in a **regular similarity search**, the retrieved documents may:

- Be very similar to each other.
- Repeat the same information.
- Lack diverse perspectives.

This can reduce the usefulness of the retrieved set, especially when variety is important.

##### Step 2: How MMR Retriever Works

MMR (Maximal Marginal Relevance) Retriever addresses this by:

1. Picking the **most relevant document** first.
2. Then selecting the **next most relevant but least similar** document to the already chosen ones.
3. Repeating this process until the desired number of documents is selected.

##### Step 3: Benefits in RAG Pipelines

This approach is particularly useful in **Retrieval-Augmented Generation (RAG)** pipelines because:

- It ensures the context window contains **diverse yet relevant** information.
- It is effective when documents are **semantically overlapping**.

##### Final Answer

MMR Retriever improves search results by balancing **relevance** and **diversity**, avoiding redundancy, and ensuring a richer set of perspectives in retrieved documents.

- **Logic:** It picks the most relevant document first, then selects the next document that is relevant but _least similar_ to the ones already picked.
- **Parameter:** Uses a **Lambda** value (0 to 1). `1` = standard similarity search; `0` = maximum diversity.

This example shows **why MMR (Maximal Marginal Relevance)** is better than normal similarity search.

##### Query:

**"Climate change effects"**

##### Documents:

- **D1:** Climate change → Arctic glaciers melting
- **D2:** Arctic glaciers melting (very similar to D1)
- **D3:** Deforestation in Amazon
- **D4:** Wildfires in California
- **D5:** Rising sea levels in coastal cities

##### Left side (Normal Similarity Search)

It only looks at **relevance** to the query.

Top 3:

1. D1 – Arctic glaciers melting
2. D2 – Arctic glaciers melting _(almost duplicate of D1)_
3. D3 – Deforestation

**Problem:** D1 and D2 provide nearly the same information, so the retrieved context lacks diversity.

##### Right side (MMR Retriever)

MMR balances:

- **Relevance** to the query
- **Diversity** (avoids selecting similar documents)

Top 3:

1. D1 – Arctic glaciers melting
2. D4 – Wildfires in California
3. D5 – Rising sea levels

**Why?**

- D1 is selected because it's highly relevant.
- D2 is skipped because it's too similar to D1.
- D4 and D5 are chosen since they discuss **different effects of climate change**, giving broader and more useful context.

##### In one line:

**Similarity Search = Most relevant documents (may contain duplicates).**  
**MMR Retriever = Relevant + Diverse documents (reduces redundancy and improves context quality).**


|Feature|Standard Similarity|MMR|
|---|---|---|
|**Result Focus**|High relevance only.|Relevance + Diversity.|
|**Best For**|Fact-checking.|Research/Broad topics.|
**Python Code - **
```
# Assuming 'vector_store' is already initialized (e.g., Chroma or FAISS)
retriever = vector_store.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 3,              # Number of documents to return
        "fetch_k": 20,       # Number of docs to pass to MMR algorithm initially
        "lambda_mult": 0.5   # 1.0 = pure similarity, 0.0 = max diversity [3]
    }
)

# Execution
results = retriever.invoke("What is LangChain?") [3]
```

###### **B. Multi-Query Retriever**

**Main Problem-** 
	Sometime a single query  might not  capture all the ways information is phrased in your documents.
	User queries can be ambiguous (e.g., "How to stay healthy" could mean diet, exercise, or sleep). 

**Solution-** It uses an LLM to generate **multiple versions** of the user's query from different perspectives.

**Example:**
Query: "How can I stay healthy?"

**Could mean:**
what should I eat?
How often should I exercise?
how can i manage stress?


A simple similarity search might miss documents that talk about those things but don't use  the word "healthy".

#### **How it works?**
1. Take your original query
2. uses LLM to generate multiple different versions of that query semantically
3. performs retrieval for each sub-query
4. combines and deduplicates the result.


- **Process:** 
	1 query → LLM → 5 queries → Parallel Retrieval → Merge & Deduplicate.
	
- **Python Code:** 
```
from langchain.retrievers.multi_query import MultiQueryRetriever
from langchain_openai import ChatOpenAI

# 1. Initialize the LLM for query generation
llm = ChatOpenAI(model="gpt-4o")

# 2. Setup the Multi-Query Retriever using a base retriever
# 'base_retriever' is typically created from your Vector Store (Chroma/FAISS)
multi_query_retriever = MultiQueryRetriever.from_llm(
    retriever=base_retriever, 
    llm=llm
)

# 3. Execution
# If the query is "How to stay healthy?", the LLM generates versions 
# about diet, exercise, and sleep to fetch a diverse set of documents.
results = multi_query_retriever.invoke("How to stay healthy?")
```

###### **C. Contextual Compression Retriever**

**Problem:** A retrieved document might be a long paragraph where only one sentence is actually relevant, wasting context tokens. 

**Solution:** It "trims" or compresses documents after retrieval, keeping only the relevant content.

## ❓ Query:

> **"What is photosynthesis?"**

### 📄 Retrieved Document (by a traditional retriever):

> "The Grand Canyon is a famous natural site.  
> **Photosynthesis is how plants convert light into energy.**  
> Many tourists visit every year."

## ❌ Problem:

- The retriever returns the **entire document/chunk**.
- Only **one sentence** is actually relevant to the query.
- The remaining text is **irrelevant noise**, which:
    - Wastes the LLM's context window.
    - Can confuse the model.
    - Increases token usage.

## ✅ What Contextual Compression Retriever does:

Returns **only the relevant part**, for example:

> **"Photosynthesis is how plants convert light into energy."**

# ⚙️ How It Works

1. **Base Retriever** (e.g., FAISS, Chroma, Pinecone) retrieves the top **N documents/chunks**.
2. A **Compressor** (usually an LLM or an embedding-based filter) is applied to each retrieved document.
3. The compressor **keeps only the parts relevant to the user's query**.
4. **Irrelevant content is discarded.**
5. The compressed results are sent to the LLM

# ✅ When to Use

- Your documents are **long** and contain **mixed information**.
- You want to **reduce the context length** sent to the LLM.
- You need to **improve answer accuracy** in RAG pipelines.
- You want to **reduce token usage and cost**.
- Your retrieved chunks contain a lot of **irrelevant text**.

- **Logic:** Base Retriever fetches documents → LLM Compressor filters irrelevant sentences → Result is a highly focused summary.

- **Benefit:** Reduces context window usage and improves answer accuracy.

**Python Code -**
```
from langchain.retrievers import ContextualCompressionRetriever
from langchain.retrievers.document_compressors import LLMChainExtractor
from langchain_openai import ChatOpenAI

# 1. Create a base retriever (standard similarity search)
base_retriever = vector_store.as_retriever() [7]

# 2. Initialize the compressor (uses an LLM to extract relevant parts)
llm = ChatOpenAI(model="gpt-4o")
compressor = LLMChainExtractor.from_llm(llm) [8]

# 3. Combine them into the compression retriever
compression_retriever = ContextualCompressionRetriever(
    base_compressor=compressor, 
    base_retriever=base_retriever
) [8]

# Execution returns only the relevant snippets instead of full paragraphs
compressed_docs = compression_retriever.invoke("How does photosynthesis work?") [8]
```
