Text splitting is the process of breaking large documents—like articles, PDFs, or books—into smaller, manageable "chunks" that an LLM can handle effectively

The second major component of the RAG (Retrieval-Augmented Generation) pipeline.


##### **Why Text Splitting is Critical**

1. **Overcoming Context Limits:** Every LLM has a maximum input size (context length). Splitting prevents breaching these thresholds.
2. **Improving Quality:** Small, focused chunks allow for higher quality embeddings and more precise semantic search results compared to processing massive documents at once.
3. **Preventing Hallucinations:** In tasks like summarization, LLMs are less likely to "drift" or hallucinate when working with concise chunks.
4. **Resource Efficiency:** Smaller chunks allow for parallel processing and lower memory usage.

---

**1. Length-Based Text Splitting (Character Text Splitter)**

This is the simplest method where text is split strictly based on a fixed character count.

- **Mechanism:** 
	- The splitter traverses the text and creates a new chunk every time it hits the defined character limit.
	- You define a size (e.g., 100 characters), and the splitter creates a new chunk every time that limit is reached.
- **Pros:** Extremely fast and conceptually simple.
- **Cons:** It ignores linguistic structure, often cutting words, sentences, or paragraphs in half, which can lead to lost context.

Example - 
- **Text:** `"Hello world, how are you?"`
- **Limit:** 10
- **Chunks:** `['Hello worl', 'd, how are', ' you?']`

**Python Example:**

```
from langchain_text_splitters import CharacterTextSplitter

text = "Your long string of text..."
splitter = CharacterTextSplitter(
    chunk_size=100, 
    chunk_overlap=0, 
    separator=""
)

chunks = splitter.split_text(text)
print(chunks)
```

---

**2. Key Concept: Chunk Overlap**

To prevent the loss of context when a text is abruptly cut, LangChain uses **Chunk Overlap**. This keeps a specified number of characters from the end of one chunk at the beginning of the next.

- **Benefit:** It "bridges" information between chunks so the model doesn't lose the meaning of a sentence cut mid-way.
- **Rule of Thumb:** For most RAG applications, a **10% to 20% overlap** is considered ideal (e.g., 20 characters for a 100-character chunk).

---

**3. Text Structure-Based (Recursive Character Text Splitter)**

This is the **most recommended and widely used splitter** in LangChain. It follows a hierarchy of separators to keep semantically related text together.

- **Separator Hierarchy:** It attempts to split by Paragraph (`\n\n`), then Line (`\n`), then Words ( ), and finally individual Characters (`""`).
- **Behavior:** It tries to make chunks as large as possible without exceeding the limit, ensuring that a sentence or paragraph is only broken if it's too large to fit in a single chunk.

**Python Example:**

```
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=100,
    chunk_overlap=20
)

chunks = splitter.split_text(text)
```

Example - 
- **Text:** `"My name is Nitish. I live in Gurgaon."`
- **Limit:** 20
- **Chunks:** `['My name is Nitish.', 'I live in Gurgaon.']` (It chooses to split at the period rather than cutting a word in half)
### How it works

It has a list of separators.

By default:

```
[
    "\n\n",   # paragraph
    "\n",     # line
    " ",      # word
    ""        # character
]
```

It always starts with the **largest separator**.

Think of it like:

```
Can I split by paragraph?

        ↓
If chunk still too big

Can I split by line?

        ↓
Still too big?

Split by words

        ↓
Still too big?

Split by characters
```

Notice it **only goes to the next separator if necessary**.

That's why it's called **recursive**.

# **4. Document Structure-Based Splitters**

This technique extends the recursive logic to specific file formats like **Code** or **Markdown**. Instead of just looking for newlines, it uses language-specific keywords to identify logical boundaries.

|Language|Primary Separators|
|---|---|
|**Python**|`class`, `def`, `if`, `for`|
|**Markdown**|`#`, `##`, `---`, `*`|
|**HTML**|`<body>`, `<div>`, `<p>`, `<li>`|

**Python Example (Code Splitting):**

```
from langchain_text_splitters import RecursiveCharacterTextSplitter, Language

python_splitter = RecursiveCharacterTextSplitter.from_language(
    language=Language.PYTHON, 
    chunk_size=200, 
    chunk_overlap=0
)
```

---

**5. Semantic Meaning-Based Splitting (Experimental)**

The most advanced method, it uses AI to understand the meaning of text. It splits documents where it detects a significant **shift in context**.

- **How it works:** It breaks text into sentences, converts them into embeddings (vectors), and compares the similarity between consecutive sentences. If the similarity drops below a certain **threshold**, it identifies a "breakpoint" and creates a new chunk.
- **Threshold Types:** Standard Deviation (default), Percentile, or Interquartile.

**Python Example:**

```
from langchain_experimental.text_splitter import SemanticChunker
from langchain_openai import OpenAIEmbeddings

splitter = SemanticChunker(
    OpenAIEmbeddings(),
    breakpoint_threshold_type="standard_deviation"
)

docs = splitter.create_documents([text])
```

**Workflow Comparison Table**

|Splitter Type|Logic|Best For|
|---|---|---|
|**Character**|Fixed length|Simple tasks, rare use cases.|
|**Recursive**|Hierarchy (`\n\n` > `\n` > )|**Standard General Text (Best Overall)**.|
|**Document**|Language keywords|Code (Python, JS) or Markdown.|
|**Semantic**|Meaning/Similarity|Complex documents with thematic shifts.|
