### **1. What is a Tool?**

Large Language Models (LLMs) are like a human body that has a brain (can think and speak) but lacks hands and legs (cannot perform actions like running code, calling APIs, or querying databases).

- **Definition:** A tool is a Python function or API packaged so that an LLM can understand its purpose and call it when needed.
- **Key Concept:** Tools allow the LLM to interact with the real world, such as booking a train ticket on IRCTC or sending a tweet.

### **2. How Tools Fit into the Agent Ecosystem**

In LangChain, an **AI Agent** is the combination of Reasoning and Action.

- **Reasoning:** Powered by the LLM (thinking step-by-step).
- **Action:** Powered by Tools (executing the task).
- **Workflow:** The Agent receives a goal → decides which tool is needed → provides inputs to that tool → receives the result → provides the final answer to the user.

### **4. Custom Tools**

You create custom tools when you need the LLM to interact with your proprietary database, product, or specific business logic.

**The 3-Step Process for Basic Custom Tools:**

1. **Function Logic:** Write a standard Python function.
2. **Type Hinting & Docstring:** Add clear input/output types and a descriptive docstring (this is how the LLM knows what the tool does).
3. **Decorator:** Apply the `@tool` decorator.

---

### **5. Three Ways to Create Custom Tools**

![[Pasted image 20260808151718.png]]

Depending on your complexity, LangChain offers three primary methods:

##### **A. Using** **@tool** **Decorator (Simplest)**

Best for 80-90% of standard use cases.

```
from langchain_core.tools import tool

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers and return the product."""
    return a * b

# Execution
print(multiply.invoke({"a": 3, "b": 5})) # Result: 15 [17]
```

##### **B. Using** **StructuredTool** **& Pydantic**

Used when you need to strictly enforce input schemas and complex validations.

```
from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field

class MultiplyInput(BaseModel):
    a: int = Field(description="First number")
    b: int = Field(description="Second number")

def multiply_func(a, b): return a * b

calc_tool = StructuredTool.from_function(
    func=multiply_func,
    name="Calculator",
    description="Multiplies two numbers",
    args_schema=MultiplyInput
) [23, 24]
```

##### **C. Inheriting from** **BaseTool** **Class**

The most advanced method. It allows for **asynchronous** tool versions and deep logic customization.

- Requires defining a `_run` method.
- Allows the creation of an `_arun` method for concurrency.

### **6. Toolkits**

A Toolkit is a collection of related tools bundled together for convenience and reusability.

- **Example:** A "Google Drive Toolkit" might contain separate tools for searching, reading, and uploading files.
- **Implementation:** You create a class with a `get_tools()` method that returns a list of tool objects.

To create a custom **Toolkit** in LangChain, you first define related tools and then bundle them into a class with a `get_tools` method. This approach ensures high **reusability** across different applications.

**Python Code: Custom Math Toolkit**

Here is the standard implementation using the `@tool` decorator as shown in the tutorial:

```
from langchain_core.tools import tool

# 1. Define your individual tools
@tool
def add(a: int, b: int) -> int:
    """Add two numbers."""
    return a + b

@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

# 2. Create the Toolkit class
class MathToolkit:
    def get_tools(self) -> list:
        # Return the list of tools you want to bundle
        return [add, multiply]

# 3. Usage
toolkit = MathToolkit()
tools = toolkit.get_tools()

# Accessing a tool from the bundle
print(tools[4].invoke({"a": 4, "b": 5})) # Output: 20
```

**Key Logic for Toolkits**

- **Encapsulation:** The toolkit class acts as a single container for multiple related functions (e.g., Google Drive tools for searching, reading, and uploading).
- **The** **get_tools()** **Method:** This is the standard method name used to retrieve the list of tool objects so they can be passed to an agent or LLM.
- **Reusability:** Once created, you can import this toolkit into any new project without rewriting the underlying tool logic.

### **Standard Tool Attributes**

Every tool in LangChain exposes three metadata attributes that the LLM uses to make decisions:

1. **.name**: The identifier of the tool.
2. **.description**: A summary of what the tool does (extracted from the docstring).
3. **.args**: The required JSON schema for the inputs.
