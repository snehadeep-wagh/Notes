
**Output Parsers** in LangChain are classes designed to convert raw, unstructured text responses from Large Language Models (LLMs) into **structured formats** like JSON, CSV, or Python objects. This is essential because while humans can understand paragraphs, machines (like databases and APIs) require structured data to function programmatically.

**All LLMs are not trained to give the structured outputs. So output parsers are used when we are using those LLMs which do not provide the structured output.**

The following are the detailed notes and code examples for the four primary output parsers discussed in the sources:

---

**1. StrOutputParser**

This is the simplest parser. Its sole purpose is to take the complex `AIMessage` object (which contains metadata like token usage) and extract only the **text content** as a plain string.

- **Why use it?** It is particularly useful when building **Chains** (pipelines). It allows the text output of one model to be passed directly into the prompt template of the next step without manual extraction.
- **Example Scenario:** Generating a detailed report on a topic and then immediately summarizing that report into five lines.

**Python Code:**

```
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import PromptTemplate
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o")
parser = StrOutputParser()

# Define Templates
template1 = PromptTemplate.from_template("Write a detailed report on {topic}")
template2 = PromptTemplate.from_template("Summarize this text in 5 lines: {text}")

# Form a Chain
# Flow: Topic -> Template1 -> Model -> Parser (String) -> Template2 -> Model -> Parser (Final String)
chain = template1 | model | parser | template2 | model | parser

result = chain.invoke({"topic": "Black Holes"})
print(result) # Directly prints the summary string [9]
```

---

**2. JsonOutputParser**

This parser "forces" the LLM to return its response in a **JSON format**. It is the quickest way to get structured data when you need a machine-readable response.

- **Limitation:** It **does not enforce a schema**. The LLM decides the keys and structure of the JSON, which may lead to inconsistency across different runs.
- **Key Function:** `parser.get_format_instructions()` is used to automatically append instructions to your prompt telling the AI to return JSON.

**Python Code:**

```
from langchain_core.output_parsers import JsonOutputParser

parser = JsonOutputParser()

# Get instructions: "Return a JSON object"
instructions = parser.get_format_instructions()

template = PromptTemplate(
    template="Give me the name, age, and city of a fictional person.\n{format_instructions}",
    input_variables=[],
    partial_variables={"format_instructions": instructions}
)

chain = template | model | parser
result = chain.invoke({}) 
print(result) # Output is a Python Dictionary: {'name': 'John', 'age': 30, 'city': 'Berlin'} [16]
```

**3. StructuredOutputParser**

This parser improves upon the `JsonOutputParser` by allowing you to **enforce a schema**. You define exactly which fields you want the LLM to return using the `ResponseSchema` class.

- **Why use it?** When you need a specific structure (e.g., "Fact 1", "Fact 2") and want to ensure the LLM uses your defined keys.
- **Limitation:** It does **not provide data validation**. For example, if you ask for an "Age" as an integer, the LLM might still return the string "35 years," and this parser won't catch the error.
- **Note:** This parser is located in the main `langchain` library, not `langchain_core`.

**Python Code:**

```
from langchain.output_parsers import ResponseSchema, StructuredOutputParser

# 1. Define the Schema
schemas = [
    ResponseSchema(name="fact_1", description="First fact about the topic"),
    ResponseSchema(name="fact_2", description="Second fact about the topic")
]

# 2. Create Parser
parser = StructuredOutputParser.from_response_schemas(schemas)

template = PromptTemplate(
    template="Give me 2 facts about {topic}.\n{format_instructions}",
    input_variables=["topic"],
    partial_variables={"format_instructions": parser.get_format_instructions()}
)

chain = template | model | parser
result = chain.invoke({"topic": "Space"})
print(result) # Follows your schema exactly [18, 19]
```

**4. PydanticOutputParser**

This is the most powerful and **recommended** parser. It uses Pydantic models to not only **enforce a schema** but also provide **strict data validation** and type safety.

- **Core Benefits:**
    - **Type Safety:** Automatically converts outputs into Python objects (e.g., converting "30" to integer 30).
    - **Validation:** Can catch errors if the LLM provides data that doesn't meet your constraints (e.g., `Age > 18`).
    - **Descriptions:** You can add field descriptions that are sent to the LLM to guide its extraction logic.

**Python Code:**

```
from langchain_core.output_parsers import PydanticOutputParser
from pydantic import BaseModel, Field

# 1. Define the Schema using Pydantic
class Person(BaseModel):
    name: str = Field(description="Name of the person")
    age: int = Field(gt=18, description="Age of the person (must be > 18)")
    city: str = Field(description="City they live in")

# 2. Create Parser
parser = PydanticOutputParser(pydantic_object=Person)

template = PromptTemplate(
    template="Generate details for a fictional {place} person.\n{format_instructions}",
    input_variables=["place"],
    partial_variables={"format_instructions": parser.get_format_instructions()}
)

chain = template | model | parser
result = chain.invoke({"place": "Indian"})

# result is a Pydantic object, accessed with dot notation
print(result.name)
print(result.age) # [25-27]
```

**Summary Table of Parsers**

|Parser|Use Case|Main Advantage|Disadvantage|
|---|---|---|---|
|**String**|Chaining|Simplifies pipelines.|Only for text.|
|**JSON**|Fast APIs|Quickest JSON output.|No schema enforcement.|
|**Structured**|Fixed keys|Enforces your schema.|No data validation.|
|**Pydantic**|Complex Apps|**Schema + Strict Validation**.|Requires Pydantic knowledge.|
