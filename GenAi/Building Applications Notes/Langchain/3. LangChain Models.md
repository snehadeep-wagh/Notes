**1. Introduction to Model Components**

The **Model component** in LangChain serves as a **common interface** to interact with various AI models, regardless of the provider. There are two primary types of models:

- **Language Models:** These follow a "text-in, text-out" philosophy, used for tasks like summarization and chatbots.
- **Embedding Models:** These take text as input and return **vectors (numbers)** that represent the contextual meaning of the text, primarily used for **Semantic Search** and **RAG-based applications**.

To run the code, you must create a virtual environment and install the necessary libraries (`langchain`, `langchain-openai`, `langchain-anthropic`, `langchain-google-genai`, `langchain-huggingface`, `python-dotenv`). API keys should be stored in a `.env` file to keep them secure.

**3. LLMs vs. Chat Models**

The sources highlight a critical distinction between traditional LLMs and modern Chat Models:

- **LLMs:** General-purpose, "stateless" models that take a string and return a string. Support for these is gradually decreasing in LangChain.
- **Chat Models:** Specialized for conversations, they take a sequence of messages and return a chat message. They support **roles** (System, Human, AI) and **conversation history**.

**A. LLM Demo (OpenAI)**

This uses the legacy string-based interface.

```
from langchain_openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

llm = OpenAI(model="gpt-3.5-turbo-instruct")
result = llm.invoke("What is the capital of India")
print(result)
```

**B. Chat Model Demo (OpenAI)**

This is the recommended approach for modern applications.

```
from langchain_openai import ChatOpenAI
from dotenv import load_dotenv

load_dotenv()

model = ChatOpenAI(model="gpt-4", temperature=0.7, max_completion_tokens=100)
result = model.invoke("What is the capital of India")
print(result.content)
```

- **Key Parameters:** **temperature** (0 to 2) controls creativity (lower is more deterministic), and **max_completion_tokens** restricts output length.

**5. Open Source Models via Hugging Face**

Open-source models allow for **full control, data privacy, and zero API costs** if run locally.

**Approach 1: Inference API (Remote Hosting)**

```
from langchain_huggingface import ChatHuggingFace, HuggingFaceEndpoint
from dotenv import load_dotenv

load_dotenv()

llm = HuggingFaceEndpoint(
    repo_id="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    task="text-generation"
)

model = ChatHuggingFace(llm=llm)
result = model.invoke("What is the capital of India")
print(result.content)
```

**Approach 2: Local Download (Running on your machine)**

_Note: This requires significant hardware resources__._

```
from langchain_huggingface import ChatHuggingFace, HuggingFacePipeline

llm = HuggingFacePipeline.from_model_id(
    model_id="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    task="text-generation",
    pipeline_kwargs={"temperature": 0.5, "max_new_tokens": 100}
)

model = ChatHuggingFace(llm=llm)
result = model.invoke("What is the capital of India")
print(result.content)
```

**6. Embedding Models**

Embedding models convert text into numerical vectors to perform **semantic searches**.

**OpenAI Embeddings****:**

```
from langchain_openai import OpenAIEmbeddings
from dotenv import load_dotenv

load_dotenv()

embeddings = OpenAIEmbeddings(model="text-embedding-3-large", dimensions=32)

# Single query
query_vector = embeddings.embed_query("Delhi is the capital of India")

# Multiple documents
docs = ["Delhi is the capital of India", "Paris is the capital of France"]
doc_vectors = embeddings.embed_documents(docs)
```

**Hugging Face Local Embeddings****:**

```
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(model_name="sentence-transformers/all-MiniLM-L6-v2")
vector = embeddings.embed_query("Delhi is the capital of India")
```

**7. Application: Document Similarity Search**

This project demonstrates how to find the most relevant document for a user query using **Cosine Similarity**.

```
from langchain_openai import OpenAIEmbeddings
from sklearn.metrics.pairwise import cosine_similarity
import numpy as np
from dotenv import load_dotenv

load_dotenv()

embeddings = OpenAIEmbeddings(model="text-embedding-3-large", dimensions=300)

documents = [
    "Virat Kohli is an Indian cricketer known for his aggressive approach.",
    "Jasprit Bumrah is an Indian fast bowler known for his yorkers.",
    "Rohit Sharma is the captain of the Indian cricket team.",
    "MS Dhoni is a former Indian captain and wicketkeeper.",
    "Sachin Tendulkar is often called the God of Cricket."
]

query = "Tell me about Bumrah"

# 1. Generate Embeddings [37]
doc_vectors = embeddings.embed_documents(documents)
query_vector = embeddings.embed_query(query)

# 2. Calculate Similarity [38]
scores = cosine_similarity([query_vector], doc_vectors)

# 3. Fetch Most Similar Document [39, 40]
index = np.argmax(scores)
print(f"Query: {query}")
print(f"Most Relevant Doc: {documents[index]}")
print(f"Similarity Score: {scores[index]}")
```

This application simulates the **Retrieval** part of a RAG system by finding the closest vector in a 300-dimensional space.
