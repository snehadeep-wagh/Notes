
# 1. Understanding Sequential Workflows

### **Detailed Explanation**

A **Sequential Workflow** is the simplest form of a graph. It is a linear path where tasks are connected in a direct line. In this pattern, the output of Task A is processed, and the flow moves immediately to Task B, then Task C, and so on. There are no decision-making branches (Routing), simultaneous tasks (Parallelization), or loops (Cycles).

### **Key Concepts**

- **Linear Execution:** Tasks follow a strict order without deviation.
- **Graph Representation:** In LangGraph, even a simple linear sequence is treated as a graph consisting of Nodes and Edges.
- **Starting and Ending:** Every graph must have an explicit entry point (`START`) and an exit point (`END`).

# 3. The LangGraph Development Lifecycle

Every LangGraph application follows a consistent four-step workflow:

|Step|Action|Description|
|:--|:--|:--|
|**1**|**Define State**|Create a `TypedDict` to act as the "shared memory" for the graph.|
|**2**|**Define Nodes**|Write Python functions that take the state, perform a task, and return updates.|
|**3**|**Define Edges**|Connect the nodes to dictate the flow of execution.|
|**4**|**Compile & Run**|Turn the definition into a "runnable" and invoke it with initial data.|

# 4. Example 1: Non-LLM Sequential Workflow (BMI Calculator)

This example focuses on the syntax without the complexity of LLM calls.

### **How It Works**

The graph takes weight and height, calculates the BMI in one node, and categorizes it (e.g., Underweight, Normal) in a second node.

### **Detailed Notes: State Definition**

In LangGraph, the state is a **Typed Dictionary**. It is a schema that tells the graph what data points to track.

```
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# Step 1: Define the State
class BMIState(TypedDict):
    weight: float
    height: float
    bmi: float
    category: str
```

### **Detailed Notes: Node Implementation**

Nodes are standard Python functions. Crucially, they receive the current `state` and must return a dictionary containing the **updates** to that state.

```
# Step 2: Define Node Functions
def calculate_bmi(state: BMIState):
    weight = state["weight"]
    height = state["height"]
    bmi = round(weight / (height ** 2), 2)
    # Return only the update
    return {"bmi": bmi}

def label_bmi(state: BMIState):
    bmi = state["bmi"]
    if bmi < 18.5:
        cat = "Underweight"
    elif bmi < 25:
        cat = "Normal"
    else:
        cat = "Overweight"
    return {"category": cat}
```

### **Detailed Notes: Graph Construction**

We use `StateGraph` to register nodes and draw the edges.

```
# Step 3: Create the Graph
builder = StateGraph(BMIState)

# Add Nodes
builder.add_node("calc_node", calculate_bmi)
builder.add_node("label_node", label_bmi)

# Add Edges
builder.add_edge(START, "calc_node")
builder.add_edge("calc_node", "label_node")
builder.add_edge("label_node", END)

# Step 4: Compile and Invoke
workflow = builder.compile()
result = workflow.invoke({"weight": 80, "height": 1.73})
print(result) # Contains weight, height, bmi, and category
```

### **Visualizing the Workflow**

```

    START((START)) --> A[calculate_bmi]
    A --> B[label_bmi]
    B --> END((END))
```

# 5. Example 2: Simple LLM QA Workflow

This example demonstrates how LangChain and LangGraph work together.

### **Detailed Notes**

- **LangChain's Role:** Provides the LLM model and prompt handling.
- **LangGraph's Role:** Orchestrates the execution.

### **Complete Python Code**

```
import os
from dotenv import load_dotenv
from langchain_openai import ChatOpenAI
from langgraph.graph import StateGraph, START, END
from typing import TypedDict

load_dotenv()
model = ChatOpenAI(model="gpt-4o")

class QAState(TypedDict):
    question: str
    answer: str

def llm_node(state: QAState):
    # Logic: Extract question -> Prompt -> Invoke -> Update
    question = state["question"]
    response = model.invoke(f"Answer this: {question}")
    return {"answer": response.content}

# Graph Setup
builder = StateGraph(QAState)
builder.add_node("qa_agent", llm_node)
builder.add_edge(START, "qa_agent")
builder.add_edge("qa_agent", END)

workflow = builder.compile()
print(workflow.invoke({"question": "What is the capital of France?"}))
```

# 6. Example 3: Prompt Chaining (Blog Generation)

**Prompt Chaining** is a sequence where multiple LLM calls are made. One call decomposes a complex task, and the next finishes it.

### **The Workflow Strategy**

1. **Node 1 (Planner):** Generates a detailed **Outline** from a Title.
2. **Node 2 (Writer):** Generates the **Blog Content** using both the Title and the Outline.

### **State Persistence Advantage**

In standard LangChain, the output of Step 1 is often replaced by Step 2. In LangGraph, because we use a **State Object**, all intermediate data (like the Outline) remains accessible at the very end of the process.

### **Complete Python Code**

```
class BlogState(TypedDict):
    title: str
    outline: str
    content: str

def generate_outline(state: BlogState):
    prompt = f"Create a detailed outline for a blog titled: {state['title']}"
    outline = model.invoke(prompt).content
    return {"outline": outline}

def generate_blog(state: BlogState):
    # Accesses both the original title and the new outline from the state
    prompt = f"Write a blog for '{state['title']}' using this outline: {state['outline']}"
    content = model.invoke(prompt).content
    return {"content": content}

# Orchestration
builder = StateGraph(BlogState)
builder.add_node("planner", generate_outline)
builder.add_node("writer", generate_blog)

builder.add_edge(START, "planner")
builder.add_edge("planner", "writer")
builder.add_edge("writer", END)

workflow = builder.compile()
final_result = workflow.invoke({"title": "The Future of AI in Education"})
```

# Final Revision Section

### **Key Takeaways**

- **Nodes are Functions:** Every task in the graph is a Python function that consumes and updates a dictionary.
- **State is Global:** Unlike simple pipes, the state object carries all history throughout the execution.
- **Hand-in-Hand:** LangGraph uses LangChain for "the thinking" (LLMs) while it provides "the skeleton" (Orchestration).

### **Important Terminology**

- **StateGraph:** The class used to define the structure of your agent.
- **TypedDict:** A specialized dictionary that defines the keys and types for your state.
- **Partial Update:** When a node returns a dictionary, it doesn't replace the whole state; it only updates the keys provided.
- **Invocation:** The process of starting the graph execution.

### **Common Mistakes and Confusions**

- **Forgetting to Return State:** If a node doesn't return a dictionary, the graph cannot update its memory.
- **Incorrect Type Hinting:** LangGraph relies on the State type for validation; ensure your node function signatures match the `TypedDict`.
- **Overkill:** Don't use LangGraph for simple, one-off LLM calls. It is designed for multi-step, evolving processes where state management is difficult in standard code.
