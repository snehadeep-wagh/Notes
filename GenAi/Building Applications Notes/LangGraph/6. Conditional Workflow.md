# 1. Understanding Conditional Workflows

### **Detailed Explanation**

A **Conditional Workflow** is a system where the path of execution is determined by a specific condition at runtime. While it may visually resemble a parallel workflow due to branching, there is a fundamental difference:

- **Parallel Workflows:** Multiple branches are executed simultaneously (e.g., Task 1 leads to Task 2 AND Task 3).
- **Conditional Workflows:** Based on a condition, the system enters **only one** branch (e.g., Task 1 leads to Task 2 OR Task 3).

### **Key Concepts**

- **Routing Logic:** The mechanism that evaluates the state and decides which node to trigger next.
- **Branching:** The point where the graph's path splits into two or more possible directions.
- **If-Else Analogy:** Just as programming relies on `if-else` for logic, LangGraph uses conditional branching to handle different scenarios in a workflow.

### **Comparison Table**

|Feature|Parallel Workflow|Conditional Workflow|
|:--|:--|:--|
|**Execution**|Simultaneous execution of branches.|Execution of a single selected branch.|
|**Logic**|"And" logic (Do this and that).|"Or" logic (Do this or that).|
|**Order**|Tasks 2 & 3 run at once.|Either Task 2 runs OR Task 3 runs.|
|**Purpose**|Efficiency and multi-perspective analysis.|Decision making and path optimization.|

# 2. How Conditional Edges Work in LangGraph

In LangGraph, transitions are handled by **Edges**. For conditional logic, we use a specialized function: `add_conditional_edges`.

### **The Mechanism**

1. **The Origin Node:** The node from which the condition is checked (e.g., "Calculate Discriminant").
2. **The Routing Function:** A separate Python function (not a node) that checks the current state and returns the string name of the next node to execute.
3. **The Target Mapping:** The graph uses the return value of the routing function to jump to the correct next node.

# 3. Example 1: Non-LLM Based (Quadratic Equation Solver)

This example uses mathematical logic to demonstrate how a graph branches based on numerical data.

### **The Mathematical Logic**

To solve \(ax^2 + bx + c = 0\), we calculate the **Discriminant (\(D = b^2 - 4ac\))**.

- **Condition 1 (\(D > 0\)):** Path leads to a node calculating two distinct real roots.
- **Condition 2 (\(D = 0\)):** Path leads to a node calculating one repeated root.
- **Condition 3 (\(D < 0\)):** Path leads to a node stating there are no real roots.

### **Visualizing the Workflow**

```
graph TD
    START((START)) --> A[Show Equation]
    A --> B[Calculate Discriminant]
    B -- "D > 0" --> C[Real Roots Node]
    B -- "D = 0" --> D[Repeated Roots Node]
    B -- "D < 0" --> E[No Real Roots Node]
    C --> END((END))
    D --> END
    E --> END
```

### **Complete Python Implementation**

```
from typing import TypedDict
from langgraph.graph import StateGraph, START, END

# Step 1: Define the State
class QuadState(TypedDict):
    a: float
    b: float
    c: float
    equation: str
    discriminant: float
    result: str

# Step 2: Define Node Functions
def show_equation(state: QuadState):
    eq = f"{state['a']}x² + {state['b']}x + {state['c']}"
    return {"equation": eq}

def calculate_discriminant(state: QuadState):
    d = (state['b']**2) - (4 * state['a'] * state['c'])
    return {"discriminant": d}

def real_roots(state: QuadState):
    d = state['discriminant']
    r1 = (-state['b'] + d**0.5) / (2 * state['a'])
    r2 = (-state['b'] - d**0.5) / (2 * state['a'])
    return {"result": f"Two roots: {r1} and {r2}"}

def repeated_roots(state: QuadState):
    root = -state['b'] / (2 * state['a'])
    return {"result": f"Repeated root: {root}"}

def no_real_roots(state: QuadState):
    return {"result": "No real roots"}

# Step 3: The Routing Function (Condition Checker)
def check_condition(state: QuadState) -> Literal["real_roots", "repeated_roots", "no_real_roots"]:
    if state['discriminant'] > 0:
        return "real_roots"
    elif state['discriminant'] == 0:
        return "repeated_roots"
    else:
        return "no_real_roots"

# Step 4: Build the Graph
builder = StateGraph(QuadState)
builder.add_node("show_eq", show_equation)
builder.add_node("calc_d", calculate_discriminant)
builder.add_node("real_roots", real_roots)
builder.add_node("repeated_roots", repeated_roots)
builder.add_node("no_real_roots", no_real_roots)

# Normal Edges
builder.add_edge(START, "show_eq")
builder.add_edge("show_eq", "calc_d")

# Conditional Edges
builder.add_conditional_edges(
    "calc_d",
    check_condition # The function that decides the path
)

# Connect everything to END
builder.add_edge("real_roots", END)
builder.add_edge("repeated_roots", END)
builder.add_edge("no_real_roots", END)

workflow = builder.compile()
```

# 4. Example 2: LLM-Based (Customer Support System)

This workflow analyzes customer reviews and branches into different response strategies based on sentiment.

### **The Strategy**

1. **Sentiment Node:** Uses an LLM with **Structured Output** to categorize a review as "Positive" or "Negative".
2. **Conditional Branch:**
    - **Positive Branch:** Generates a warm thank-you message.
    - **Negative Branch:** Triggers a **Diagnosis** node to extract the Issue Type, Tone, and Urgency before generating an empathetic resolution.

### **Visualizing the Workflow**

```
graph TD
    START((START)) --> A[Find Sentiment]
    A -- "Positive" --> B[Positive Response]
    A -- "Negative" --> C[Run Diagnosis]
    C --> D[Negative Response]
    B --> END((END))
    D --> END
```

### **Detailed Notes: Structured Output & Schemas**

For the LLM to drive logic (routing), it must return data in a consistent format (JSON). We use **Pydantic Schemas** for this.

```
from pydantic import BaseModel, Field
from typing import Literal

# Schema for Sentiment Analysis
class SentimentSchema(BaseModel):
    sentiment: Literal["positive", "negative"] = Field(description="Review sentiment")

# Schema for Negative Review Diagnosis
class DiagnosisSchema(BaseModel):
    issue_type: Literal["bug", "ui", "performance", "support"]
    tone: str
    urgency: Literal["low", "medium", "high"]
```

### **Key Logic: Negative Path Diagnosis**

When a review is negative, we don't just reply. We analyze the **Diagnosis State** to make the response more "favorable" and helpful to the customer.

### **Complete Python Implementation Snippet**

_(Focusing on the routing and LLM logic)_

```
# The Routing Function
def check_sentiment(state: ReviewState):
    if state['sentiment'] == "positive":
        return "positive_response"
    else:
        return "run_diagnosis"

# Building the Conditional Logic
builder.add_conditional_edges(
    "find_sentiment",
    check_sentiment
)

# Execution Flow for Negative Path
builder.add_edge("run_diagnosis", "negative_response")
builder.add_edge("negative_response", END)
```

# Final Revision Section

### **Key Takeaways**

- **Routing Function is King:** In conditional workflows, the routing function determines the path of the graph by returning a node's name.
- **Stateful Decision Making:** Decisions are made based on values stored in the `State` dictionary (like `sentiment` or `discriminant`).
- **Visual Distinction:** In LangGraph visualizations, conditional edges are often represented by **dotted lines**, signifying that only one path will be active.

### **Important Terminology**

- **add_conditional_edges:** The LangGraph function used to implement branching.
- **Structured Output:** Forcing an LLM to return JSON so its "thoughts" can be used as variables in code.
- **Literal:** A type-hinting tool used to restrict LLM outputs to a specific set of choices (e.g., "positive" or "negative").
